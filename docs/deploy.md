# Publishing the app (R15)

The app is a static Vite build. `vercel.json` sets the build command, the output folder (`app/dist`) and a rewrite of every route to `index.html`, so `/app`, `/auditor` and `/settings` open directly. Routes under `/api/` are left to the functions.

The build runs `node scripts/ensure-clients.mjs` first. `app-lib/clients/index.ts` is generated by `stellar scaffold build` and is not in git, and Vercel has neither Rust nor the Stellar CLI, so the script writes the testnet `options` the app reads when the file is missing. It never overwrites a generated file. `app/.env.production` holds the public testnet addresses (no secrets), so the build itself needs no dashboard variables. USDC funding uses Circle's public testnet faucet and does not require a server secret.

## Steps (needs the team's Vercel account)

1. In Vercel: **Add New → Project**, import `Dabuca/arqueo` (the repo is private; allow the GitHub integration to read it).
2. Production branch: `develop` (or `main` once merged). Leave the build settings: they come from `vercel.json`.
3. Deploy. Open `<url>/auditor` directly and check the **Testnet only** strip is visible.
4. Put the URL in the README header and in the form answers, then tick R15 in `AGENTS.md`.

Or from a terminal, once logged in: `npx vercel --prod`.

## Things to know

- Passkeys and the company account live in the browser of each visitor: on the published URL, create a new company account (the one made on localhost does not carry over).
- To show the manager signing on a phone (R20), create the company account on the published URL with "Register the manager's passkey on a phone" ticked. A passkey is bound to the domain it was created on, so one made on localhost will not work on the published URL. Use Chrome or Edge with Bluetooth on, near the phone.
- Record the final video on the published URL so HTTPS and the testnet notice are visible.
- Do not put secret keys (`S…`) in `app/.env.production`.

## Test USDC funding (R18)

In the app, prepare a temporary G... funding address, open
[Circle's testnet faucet](https://faucet.circle.com/), choose Stellar testnet,
and request USDC. Circle's faucet UI controls eligibility and request limits.
Request USDC to the prepared G... address, then use **Transfer USDC to treasury**. Circle's faucet funds classic Stellar accounts; the transfer to the smart account is signed locally
by that temporary testnet account; its secret stays in browser storage and is
discarded after the transfer. No issuer secret or faucet API is used by the
server. The app checks that the account exists and has the Circle USDC
trustline before submitting a payment, so failures are explained before the
smart-account simulation.

`PUBLIC_CONTROL_POLICY_ADDRESS` must point to the R18 deployment with spend
state keyed by token contract for XLM. Keep the existing deployment in
`PUBLIC_USDC_CONTROL_POLICY_ADDRESS` so USDC keeps its previous on-chain cap
state. The R18 app applies the same numeric limit values to both assets and
tracks spent amounts independently.
