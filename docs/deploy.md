# Publishing the app (R15)

The app is a static Vite build. `vercel.json` sets the build command, the output folder (`app/dist`) and a rewrite of every route to `index.html`, so `/app`, `/auditor` and `/settings` open directly. Routes under `/api/` are left to the functions.

The build runs `node scripts/ensure-clients.mjs` first. `app-lib/clients/index.ts` is generated by `stellar scaffold build` and is not in git, and Vercel has neither Rust nor the Stellar CLI, so the script writes the testnet `options` the app reads when the file is missing. It never overwrites a generated file. `app/.env.production` holds the public testnet addresses (no secrets), so the build itself needs no dashboard variables. Funding with test USDC needs one server secret, `USDC_ISSUER_SECRET` (see below).

## Steps (needs the team's Vercel account)

1. In Vercel: **Add New → Project**, import `Dabuca/arqueo` (the repo is private; allow the GitHub integration to read it).
2. Production branch: `develop` (or `main` once merged). Leave the build settings: they come from `vercel.json`.
3. Deploy. Open `<url>/auditor` directly and check the **Testnet only** strip is visible.
4. Put the URL in the README header and in the form answers, then tick R15 in `AGENTS.md`.

Or from a terminal, once logged in: `npx vercel --prod`.

## Things to know

- Passkeys and the company account live in the browser of each visitor: on the published URL, create a new company account (the one made on localhost does not carry over).
- Record the final video on the published URL so HTTPS and the testnet notice are visible.
- Do not put secret keys (`S…`) in `app/.env.production`.

## Test USDC funding (R18)

The company account is funded with test USDC by `api/fund-usdc.ts`, which signs with the issuer key. That key is a server secret: add it in Vercel and never give it a `PUBLIC_` name.

1. In Vercel: **Settings → Environment Variables** → add `USDC_ISSUER_SECRET` with the issuer's secret key (`S…`), for Production. Get it on your machine with `stellar keys secret usdc-issuer`, and paste it straight into Vercel without sharing it anywhere else.
2. Redeploy so the function sees the variable (**Deployments → ⋯ → Redeploy**).
3. Check it: in the published app, create the company account and press **Fund with test USDC**. Without the variable, the endpoint answers 503.

Locally, the same secret goes in `app/.env.local` (git-ignored). `npm run dev` serves `/api/fund-usdc` itself.

The function may run for up to 30 seconds (`maxDuration` in `vercel.json`). It takes at most 10,000 USDC per request and 3 requests per recipient per hour; a failed transfer does not count. Whatever goes wrong, it answers with JSON (400, 405, 429, 502 or 503) and never throws out of the request. The per-recipient limit lives in memory, so it is per serverless instance: a best-effort brake, not a hard limit.
